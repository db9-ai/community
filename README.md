# DB9 Community

Bug reports, feature requests, and feedback for [DB9](https://db9.ai) — serverless Postgres for AI agents.

## How to contribute

- **Bug report** — Something broken? [Open a bug report](https://github.com/db9-ai/community/issues/new?template=bug_report.yml)
- **Feature request** — Have an idea? [Request a feature](https://github.com/db9-ai/community/issues/new?template=feature_request.yml)
- **Question** — Need help? [Ask a question](https://github.com/db9-ai/community/issues/new?template=question.yml)

## Before opening an issue

1. **Search first** — Your issue may already exist. Check [open issues](https://github.com/db9-ai/community/issues) and [closed issues](https://github.com/db9-ai/community/issues?q=is%3Aissue+is%3Aclosed).
2. **One issue per report** — Keep each issue focused on a single bug or request.
3. **Include reproduction steps** — For bugs, minimal steps to reproduce help us fix things faster.
4. **Redact before posting** — Issues and attachments are public. Remove API tokens, passwords, connection strings, session cookies, private keys, and customer data from logs, SQL, screenshots, and URLs. Use fictional data and the smallest useful example.

## Security

If you discover a security vulnerability, **do not open a public issue**. Email [security@db9.ai](mailto:security@db9.ai) instead.

Read the [security reporting policy](SECURITY.md) for what to include and what to do if a credential was accidentally posted. Public forms do not automatically redact sensitive information.

## Repository maintenance

Changes to this repository's security policy, contacts, and forms require a pull request and another maintainer's approval. Main-branch protection enforces review, dismisses approvals after changes, and prohibits force pushes and deletion, including for administrators. Check the actual repository settings when verifying this control; a policy file alone does not enforce it.
