# Security reporting

This repository is a public community tracker for DB9. Do not submit suspected vulnerabilities, exploit details, credentials, or customer data in public issues, pull requests, comments, or Discord messages.

Report suspected DB9 vulnerabilities privately to **[security@db9.ai](mailto:security@db9.ai)**, the security contact listed in this repository. This policy does not enable GitHub's separate private vulnerability reporting feature.

Include the affected component and version, the expected and observed behavior, the potential impact, and minimal reproduction steps using test accounts and fictional data. Do not include live API tokens, passwords, private keys, full connection strings, session cookies, or database dumps. If more sensitive evidence is needed, ask for an appropriate private transfer method first.

Ordinary non-security bugs, questions, and feature requests belong in the public issue forms. Before posting, remove secrets from logs, command output, SQL, screenshots, URLs, and attachments. Keep only the information needed to reproduce the problem; replace real customer records with fictional examples. The forms do not automatically redact submitted content.

If a credential has already been posted publicly, revoke or rotate it through its issuing service promptly. Remove the sensitive content from the public post and privately send the security contact a link and a description of the exposure, without repeating the credential. Editing or deleting a post does not invalidate a leaked credential or remove copies others may have retained.

## Maintaining this policy

Changes to security contacts, reporting links, and issue forms must use a pull request reviewed by another maintainer. Verify a proposed contact change through an established trusted channel; a syntactically valid address or URL is not proof that it belongs to DB9. Keep this policy, the README, and all issue forms consistent.
